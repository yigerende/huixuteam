# 退款执行集成（仅供服务端维护）

本文件和 runtime 仅供源码维护，不得作为网站静态资源部署。客户仅看通用进度；管理员角色可看脱敏单字阶段，不能读取协议或原始内部日志。

## 业务定义

客户仅提交 email、password、totp_secret 并确认授权。网页和 /open/v1/requests 共用受理、校验、幂等、加密凭据和积分冻结逻辑。

使用原 Space Pro 合并空间 2.0：上游明确受理导出停用，且子号成功移出团队后，申请标记 succeeded，一次性结算提交时锁定的服务费。不等待退款实际到账。用户另行授权的套餐兜底见下文：确认移出后重新登录，实时核验为个人 Free 时可按业务规则完成，不伪造停用受理事实。

同母号严格串行，不同母号可并行（配置 1～8）。功能默认关闭，需先在后台配置子号全局代理和各母号专属代理。本项目不共享 Space 数据库或自动补货逻辑。

队列调度可设置同母号接单间隔（0～86400 秒，默认 0）。从上一单成功移出并完成时的持久化 completed_at 开始计时，新单只分配给已过间隔的母号；设置修改立即用于下一次领取判断，重启不重置计时。其他母号可并行，已占用母号的原申请恢复/续跑不受该间隔阻止。后台约每 2 秒调度一次，实际领取在到期后的下一轮；没有空闲资源时网页/API 申请统一按受理时间排队。客户列表、详情及公开查询仅返回通用排队说明，不返回母号数量、间隔、代理或内部执行步骤。

## 执行与恢复

1. PostgreSQL 调度事务锁分配空闲母号并保存租约，部分唯一索引保证一个母号只能占用一个未释放任务。母号邮箱和团队 ID 唯一，防止重复录入规避串行。
2. 只查询和邀请本次申请账号，不清理整个团队。
3. 使用原密码/TOTP 协议，选择目标团队并检查真实 AT 团队与邮箱。额外邮箱码/身份验证进入待跟进，不猜测验证资料。
4. 子号登录、重登及导出停用始终固定使用本次领取的全局代理，提交使用登录后的同一 curl_cffi 会话；母号查成员、邀请和移出请求使用其专属代理。两个出口不混用，不回退直连。沿用原 merge_v2.py 的 bodyless POST、固定头、Chrome impersonation、Safari UA、60 秒超时、无 chatgpt-account-id。AT 获取时间必须小于 120 秒，在持久检查点后立即再次验证。
5. 只有 2xx + JSON 布尔 success:true 才保存受理。明确拒绝可以在次数上限内重新登录。5xx、模糊成功、重定向、超时保留未知状态，不直接重发；启用套餐兜底后按下文独立流程移出和核验。
6. 受理后只移出本次子号；异常恢复不重新邀请/登录/提交。删除成员响应丢失时，完整查询确认目标已不存在后完成。
7. 完成、费用结算、通知、释放母号在同一事务中；重复通知和旧租约不能重复扣费。
8. 租约每 15 秒续期、90 秒过期，单次最长 15 分钟。异常恢复默认启用，按持久计划从原阶段恢复；未知提交按套餐兜底配置核验，关闭兜底时只读核实；受理后只清理。超过上限进入待跟进，保持母号占用及积分冻结。
9. 管理员可以核实后续跑；未知提交须先确认结果，已受理不可改成失败或重新提交。确认未完成并已清理本次资源后才能释放费用及母号。操作留通用审计，不返回内部阶段。
10. 关闭服务只停止领取新任务，已开始任务继续完成；修复配置再开启后继续队列。在用母号不能更换身份/团队/席位，运行中不能更换 AT 或代理。
11. 跨客户的同一上游账号也不能重复提交活动或已完成申请，提示不暴露其他客户身份。

## 异常恢复与占用告警

### 提交响应状态码核验（2026-10-30）

服务资源与调度 → 异常恢复与占用告警新增“提交后转入结果核验的状态码”。默认 `404`，页面支持英文逗号分隔（例如 `404,409`）；后端保存为 `recovery.verification_http_statuses` 整数数组，限 400～599、最多30个且不能重复。显式空数组关闭额外匹配；旧客户端省略字段时保留数据库值，迁移只为缺少字段的配置补默认，不重置其他设置。

仅影响最后提交阶段的响应，不作用于密码、2FA、母号查询或成员清理。2xx 且 `success:true` 仍优先记录明确受理。命中配置后同步保存 submitting 与 `verification_only=true`，不走 rejected、不直接结束失败。配置后来修改、服务重启及旧执行晚到均不能把已记录的核验请求变回自动提交。

自动恢复及套餐兜底开启时，沿用原单、子号代理和母号代理进行有限核验；间隔/上限复用兜底 `retry_seconds` / `max_attempts`，默认30秒、3次。这类申请确认仍为付费套餐也只继续核验，不重新邀请或再次提交；Free按原身份和实时套餐规则完成且只结算一次，受理时间不伪造。未知、失败或仍付费耗尽后转待跟进，冻结费保留。

只有确认精确子号的成员和邀请均已清除，才持久记录 `mother_released_at` 并释放母号调度占用；执行和费用的 `released` 仍保持 false，防止重复申请或提前退款。新单遵守从该清理确认时间开始的同母号间隔，唯一索引保证未清理的母号仍独占。人工恢复已移出申请使用个人套餐核验，不再尝试团队会话。未开启套餐兜底时仍按原只读核实；未确认清理的母号不会提前释放。

最终提交响应新增原有异步白名单证据采集：状态、耗时、响应类别、已知错误码、挑战页标记和重试提示；没有原始响应正文、凭据或新诊断下载接口。管理员单字时间线显示待核实与套餐核验结果，普通客户仅显示通用进度。历史已失败并释放的申请不会自动重办、改成功或补扣费。

### 登录 401 分类、恢复与失败收尾

HTTP 401 本身只表示本次登录认证未通过，不能证明密码填写错误。子号密码 POST 返回 401，且当前响应没有明确的 `incorrect_password` / `invalid_password` 错误码时，记录 `login_auth_failed`，不写终止标记、不立即清理，重新建立登录会话后重试。账号停用/删除等明确错误优先按原规则处理；母号授权、MFA 或其他步骤的 401 不套用密码错误判断，也不靠旧状态或错误文案猜测。

沿用运营控制台 → 服务资源与调度的既有配置：开启异常恢复时，每次执行只尝试一次，由数据库持久调度，首次失败后最多按“自动重试次数”（默认 3 次）重新登录，等待“重试间隔（秒）”；等待不占工作租约，保留原申请、母号和子号代理配置，重启不重置次数。关闭自动恢复时，只按“登录尝试次数”及同一重试间隔进行本轮有限重试；用尽后按原规则跟进。没有新增无限重试或忽略用户开关。

只在精确的子号密码 POST 响应为 401 且明确返回上述密码错误码时，写入私有兼容终止标记 `password_verification_failed`；Go 检查点同时校验阶段、请求侧、状态码及明确错误原因。此后只清理，不重新登录或提交。普通 401 的重试耗尽后，按“明确未受理且重试结束后清理”配置收尾；已提交未知或已受理的任务继续遵守原有核实与移出规则，不因登录错误重发停用。

清理仅针对本申请邮箱的普通成员或待接受邀请：校验邮箱、非空邀请 ID 和角色后，向团队 `/invites` 发起 DELETE，JSON 为 `{"email_address":"本申请邮箱"}`，随后完整复查成员与邀请均不存在。不使用返回 405 的 `/invites/{邀请ID}`；2xx、404 或网络异常本身不证明清理完成。确认清理后在同一事务中结束 failed、释放冻结费用及母号，不结算服务费。明确密码拒绝的清理不受登录恢复开关影响，失败仍按原清理间隔（默认 15/30/60 秒）有限重试，超限保留占用跟进。

客户、管理员列表/详情、通知、时间线及公开 API 不再把 401 描述为密码错误；已有终止记录统一显示“登录验证未通过（401）”及实际收尾状态，对外 `error_code: login_verification_failed`、`http_status: 401`，查询接口仍返回 HTTP 200。历史消息读取时规范化，不改原始事件、账本或重启已结束的申请。网页兼容旧错误码；协议、上游错误码及诊断细节保持私有。新产生的普通 401 等待重试时，客户仍只看到通用进度。

### 办理前母号异常自动换号

队列调度新增独立配置 `mother_failover`：默认启用，最多换 3 次，每次排队前等待 30 秒（可设置 0～10 次、5～3600 秒）。初次分配后先通过母号专属代理进行只读检查，只有持久步骤仍为 assigned、尚无邀请/子号身份/受理记录时才能换号。邀请已开始、登录中、提交未知或已受理任务始终保留原母号，不自动跨团队重做。

只读检查失败会释放执行并发及原母号占用，原申请、提交时间、锁定费用和子号代理不变，重新进入网页/API 共用的队列。换号同样遵守并行上限和同母号完成后的接单间隔，不抢占忙碌母号；没有可用母号时保留排队，等待本身不消耗换号次数。同一母号的同一凭证/代理配置不会在同一申请中循环尝试；更新凭证或代理后可重新参选，总次数仍受上限约束。关闭队列或换号开关暂停等待领取；次数耗尽转待跟进。

已知过期 AT 不分配新单；预检返回 401 的凭证标记不可用，更新凭证或对当前配置校验通过后恢复。旧执行的失败结果不能阻断后来更新的凭证。所有换号记录持久化，旧租约不能覆盖新母号执行；冻结费用不重复，成功后仍由原完成事务结算一次。客户仅看到通用排队提示；管理员时间线显示“候”和换号次数，不含核心请求详情。

运营控制台 → 服务资源与调度 → 异常恢复与占用告警，可配置以下默认值：

| 配置 | 默认行为 |
| --- | --- |
| 启用自动恢复与只读核实 | 开启 |
| 自动重试次数 | 首次失败后最多 3 次，间隔沿用队列“重试间隔（秒）” |
| 核实各轮间隔 | 上一轮结束后 30、60、120、300 秒 |
| 清理各轮间隔 | 上一轮结束后 15、30、60 秒 |
| 异常占用告警 | 首次异常后 600 秒仍未释放，在申请全监控突出显示 |
| 明确未受理且重试结束后清理 | 开启；安全核对通过才释放费用及母号 |

等待期间不持工作租约、不占并发名额，但母号仍独占；其他母号可继续工作。计划、次数、原子号出口及原母号保存到 PostgreSQL，重启不重置次数。领取在数据库锁后重新核对到期时间，旧执行器不能覆盖新租约。关闭自动恢复不打断在途请求，延后计划暂停；重新开启继续原计划。队列总开关只限制新申请领取，已开始任务继续恢复。原先未启用恢复的待跟进记录，只对未知提交或已受理的清理阶段自动登记一次，耗尽后不会无穷重新登记。

连接未建立（curl 5/6/7）属于未发出请求，可安排重试；curl 35 只有当前失败响应保存的 HTTP 状态、REQUEST_SIZE、APPCONNECT_TIME_T、REDIRECT_COUNT 都是明确整数 0 时才判定 TLS 握手前未发送，按原配置间隔重新登录后重试。缺失数据或 curl 28/55/56 不适用此判断；请求超时、响应丢失、5xx 或含糊成功保持未知。记录受理检查点的数据库写入失败可有限重试保存，不能因此重发上游请求。已明确受理后，仅执行原子号移出及查询确认，不重新邀请、登录或提交。

关闭套餐兜底时，未知提交使用原子号代理重新登录目标团队，并查询个人空间，与提交前基线比较；这不是上游退款最终状态接口。个人空间仍可见、已消失、停用、变更或查询失败都不能单独证明该申请已受理。系统不会依据这些结果自动结算、重新提交或提前移出；核实耗尽后由管理员凭可信受理依据确认，再恢复移出和一次性结算。明确未受理且重试耗尽时，只清理本次精确匹配的普通成员或待接受邀请；邀请按上述已验证的邮箱撤销方式处理。如无法确认成员与邀请均已清除，保留占用并告警，不能假装已释放。

内部只存白名单诊断代码、HTTP 状态、数字网络错误和耗时，不存原始响应、异常文本、URL、请求头或凭据。管理员时间线仅显示固定中文原因、次数与时间，新增“核”阶段；原有通用监控仅增加占用告警、是否等待恢复和下次时间。客户/API 不返回内部证据。管理员仍需有 `admin.refunds.timeline` 权限才能查看完整脱敏流程记录。

### 停用待核实的套餐兜底（2026-10-28）

运营控制台 → 服务资源与调度 → 停用待核实：移出后套餐兜底。默认开启，间隔 30 秒，最多 2 轮，每轮总共最多尝试 3 次；分别可配 5～3600 秒、1～5 轮和 1～10 次。自动恢复总开关与此开关共同控制尚未领取的核验/再次邀请，已有执行自然结束。旧客户端保存其它设置时不覆盖已配置的兜底开关。

1. 仅针对 submitting（停用结果未知），保留原申请、原冻结费、原母号独占和子号出口。已明确受理仍只做原清理，不走本兜底。
2. 母号经自身专属代理，只移出身份及邮箱匹配的普通成员，并完整确认该子号成员及邀请都不存在。没有确认移出就不查询套餐；检查点持久保存，重启后不会凭空假定移出。
3. 子号经原全局代理使用现有密码/TOTP流程重新登录个人空间，验证 Session/AT 邮箱、用户ID及个人空间ID；不能使用团队 AT 或旧缓存。通过 /me 校验身份，再实时查询 accounts/check，与 Space 获取 GPT 信息使用相同套餐来源。多空间无法唯一确定、接口失败、非个人空间或未知套餐都不能结算。
4. 明确 Free：事务内完成、结算一次并释放母号，completion_basis=plan_free；accepted_at 保持真实原值，页面显示“已确认（兜底依据）”，不写成上游已受理或退款到账。
   套餐接口可能保留旧 `subscription_plan`。认证后的个人空间明确 `plan_type=free` 且 `has_active_subscription=false` 时，以当前Free为准；其他字段相互矛盾、有效订阅标记不是布尔值、未知套餐或信息缺失均不完成。兼容 `chatgptpro` / `chatgptproplan` 等常见套餐名称，但不能仅凭旧订阅名称认定当前仍付费。
5. 明确仍为个人付费套餐：原单等待配置间隔，再邀请并走原完整流程，不新增申请或冻结费用。再次结果未知受轮次上限约束；查询失败仅重试移出/登录/核验阶段，不直接重办。超限转待跟进并保留必要资源和冻结费。
6. 管理员服务单时间线显示移、登、验、复、停、结及开始结束时间、耗时、固定中文结果。客户/API保持通用进度；端点、请求内容、凭据和原始异常只在服务端，不随时间线返回。

私有诊断增加 tls_before_request 传输状态与固定兜底阶段。它们仍走异步白名单通道；状态检查点和资金事务保持同步。此规则是用户明确选择的服务完成依据，不能用 Free 证明退款到账，也不能保证网络永远不失败。

提交继承登录会话的固定 Chrome TLS 配置（当前 chrome131），不再覆盖为随依赖版本变化的 chrome 别名（curl_cffi 0.16 当前映射 chrome146）。正式环境无凭据的只读对照测试证明，覆盖会额外建立代理隧道，并使动态子号代理更换出口；继承配置可复用既有连接。请求头、无请求体、60秒超时、证书校验和代理归属保持原协议。连接被对端关闭时仍可能重新建连，本修复不能保证动态代理永久稳定。

### 私有异步诊断证据（2026-10-27）

#### 登录团队信息观察（2026-10-31）

本次仅增加异步记录，未增加套餐准入或其他办理判断。密码/TOTP 验证完成后、跟随回调前记录 `authenticated_before_callback`；执行目标团队选择前再记录 `before_team_select`，使用此刻更新的授权会话信息。移出后个人登录的选择前记录 `before_personal_select`。初次登录、重新登录及核验登录均经过相同观察位置。

记录只读取登录响应／Cookie 已解析的 `workspaces`，不新增 HTTP 请求、额外登录、等待或同步写库。仅服务端私有诊断保存有界空间 ID、空间类别、角色、是否目标团队、上游明确提供的个人/默认空间布尔标志，以及固定套餐字段中符合格式的原始标识。未知套餐标识保留，不擅自映射 Plus/Pro 档位；邮箱、团队名称、凭据、Cookie 原文、请求地址及完整响应不记录，不增加浏览器读取入口。仅出现在授权空间列表不证明已加入团队，也不能单凭空间列表确定实际订阅。

上游未返回列表／套餐字段则明确记录缺失，读取异常记 unavailable；不补查套餐，不改变登录、选择空间、重试、提交、清理、核验或资金处理。普通诊断每次执行仍最多 128 条，团队观察独立预留最多 16 条，合计最多 144 条，每条最多 16 个空间；因此普通请求日志截断不会先占用团队观察配额。仍使用原有非阻塞异步批量写库通道，异常不传播回业务流程。极端队列溢出或进程强制退出仍可能丢失未落盘日志。

登录、邀请、个人空间核实、停用提交和移出记录请求开始、响应及失败证据。保留固定阶段名、子号/母号请求侧、HTTP 状态、curl 数字错误码、代理 CONNECT 状态、已知上游错误代码、挑战页标记、Retry-After、异常类型、本地源码文件与行号、耗时、观测时间及传输重试序号；未知原始文本、URL、请求体、响应体、Cookie、邮箱及任何凭据均不记录。源码版本由正式镜像标签定位。Python 与 Go 两层白名单，不依赖正则替换秘密后保留原文。

每次执行的租约仅保存不可逆摘要作为关联编号，并绑定当次重试/核实/清理计数及资源ID（不含凭据）。数据仅在服务端 `refund_execution_diagnostics.diagnostic`；不增加网页、管理员或对外 API 下载/查询入口。查看现有管理员详情和时间线不会得到这些证据。

诊断走单向消息，无业务 RPC 应答；Go 为每次执行设置容量128的非阻塞队列，每100ms或16条后台批量写库，写入超时2秒，不占业务行锁，不修改申请状态或费用。Python每次执行最多128条，超额保留截断标记；Go队列满只丢诊断并记录数量，数据库写失败将该批脱敏证据写入容器日志兜底。业务请求不等待诊断存储，结束后后台继续排空；正常服务关闭时等待排空。强制断电/进程被杀时未刷新的内存事件可能丢失，不能承诺零丢失。

执行器启动、管道/协议损坏、超时、取消、非零退出、检查点持久化失败也保存固定原因；受理事实仍使用原同步事务确认，不能用异步诊断代替。异步插入只追加，不覆盖最后业务诊断，旧执行的晚到日志不能修改新执行状态；重试成功后之前的失败证据继续保留。排查优先按观测时间、执行关联编号及序号排序，插入时间可能因异步写入略后。

## 展示和保密

### 登录下一步缺失与额外验证（2026-10-30）

登录标识与密码响应分别检查下一步。响应缺少页面类型和继续地址、且没有明确错误或验证要求时，记录 `login_response_incomplete`，按现有自动恢复次数与重试间隔重新登录原账号；原申请、母号、代理配置及冻结费用保留，不在工作进程里立即循环重试。耗尽后按失败清理配置收尾。

明确邮箱验证不会自动尝试规避验证。未提交的申请在“异常恢复”和“失败清理”均开启时，按清理间隔移出本次账号、撤销其邀请，并确认两者不存在后失败释放；清理尚未确认就不释放，清理失败仍有限重试。关闭相关配置则保持人工跟进。未知提交和已受理申请继续原核验/移出规则，不能因此重新提交或误释放。

私有异步诊断新增页面类别、下一步地址类别及验证方式枚举；未知内容只记 other/missing，不保存原始页面、URL或凭据，不增加浏览器查询入口。旧记录缺失这些字段时不能反推当时具体验证分支。

客户、公开 API、通知与导出只看通用时间线：申请已受理、开始处理、处理时间延长，正在继续、退款服务已完成，以及对应时间。延长提示仅实际执行时最多每 60 秒一次。

申请、管理、列表、通知、导出和 API 文档不返回原始内部检查点、上游 URL、请求/响应体、团队 AT 或原始诊断。私有事件单独标记并过滤，历史未知消息也通过白名单处理。

2026-10-26 用户授权新增申请全监控详情的办理记录：提、候、邀、登、团、停、移、结。GET /api/admin/refunds/{id}/timeline 与独立 admin-timeline 静态包受管理员专属 admin.refunds.timeline 权限保护（仅 admin 角色，operator 不可访问）；普通用户、匿名和 API key 无权读取。接口通过只读一致性数据库快照，把精确白名单事件转为固定 DTO，未知消息直接丢弃，不读取或返回凭据、代理或母号身份。查看与刷新不调用执行器、不续租、不推进状态、不结算费用。缺失历史时间不推算，重试独立记录；停已受理不代表退款到账。详情打开才加载，活动申请每 10 秒读取，终态停止，关闭/换申请取消旧请求与定时器。对外 API 和客户详情不增加这些阶段。

客户端只调用本项目业务 API；所有核心上游操作在服务端完成。母号 AT、可选 RT、代理 URL、客户凭据使用独立 AAD 的 AES-GCM 加密；管理列表不回显密钥，编辑留空保留。母号录入支持 Session JSON/AT、JSON 文件和安全元信息预览；解析、校验接口受管理员权限限制，仅返回身份元信息或通用校验结果。协议凭据仅通过进程 stdin 和内存传递，原始诊断不进入浏览器或应用日志。

子号全局选择记录在 refund_settings.child_proxy_id，领取时保存至 refund_execution.child_proxy_id，续跑不会跟随新的全局选择。正在使用的子号及母号代理不能改地址；完成受理后的清理只需要母号代理，不因全局子号出口暂停而重复提交或阻止清理。历史配置不自动选择出口，缺少全局代理的新请求继续排队。

管理模块拆分为受 Cookie 权限保护的静态分包，Cache-Control 为 private, no-store。生产不生成 source map。内部文档、源码、环境变量文件无下载入口。
